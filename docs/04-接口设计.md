# AI PR Review 助手接口设计文档

## 1. 文档说明

本文档用于说明「AI PR Review 助手」后端 REST API 的接口设计，包括通用约定、数据结构、接口详情、错误处理和前后端联调说明。

本项目第一版面向 3 天比赛 MVP，接口设计优先服务以下核心链路：

```text
输入 GitHub Pull Request 链接
→ 解析 PR 地址
→ 获取 GitHub PR 信息、提交记录、变更文件和 diff
→ 预处理 diff
→ 执行规则扫描和 AI Review
→ 返回结构化 Review 报告
→ 前端展示 PR 总结、风险识别、Review 建议和测试建议
```

第一版不设计用户登录、权限、多租户、Webhook、自动评论到 GitHub 等复杂功能。

## 2. 接口通用约定

### 2.1 基础路径

所有接口统一以 `/api` 开头。

开发环境后端地址：

```text
http://localhost:8080
```

前端开发环境建议通过 Vite 代理访问后端：

```text
/api -> http://localhost:8080
```

### 2.2 请求格式

接口请求体统一使用 JSON。

请求头：

```http
Content-Type: application/json
Accept: application/json
```

字段命名统一使用 camelCase。

示例：

```json
{
  "prUrl": "https://github.com/owner/repo/pull/12"
}
```

### 2.3 统一响应格式

所有接口统一返回 `Result<T>`。

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

字段说明：

| 字段 | 类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| code | number | 是 | 状态码，0 表示成功，非 0 表示失败 |
| message | string | 是 | 提示信息，成功时通常为 `success` |
| data | object / array / null | 否 | 具体业务数据，失败时为 `null` |

成功响应示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "status": "UP"
  }
}
```

### 2.4 错误响应格式

错误响应仍使用统一 `Result<T>` 结构，`code` 不为 0。

```json
{
  "code": 40001,
  "message": "PR 链接不能为空",
  "data": null
}
```

建议 HTTP 状态码：

| HTTP 状态码 | 场景 |
| --- | --- |
| 200 | 请求成功 |
| 400 | 参数错误，例如 PR 链接为空或格式错误 |
| 403 | GitHub API 限流、私有仓库无权限访问 |
| 404 | GitHub 仓库不存在或 PR 不存在 |
| 422 | PR diff 为空或 PR 内容无法分析 |
| 500 | 系统内部异常 |
| 502 | GitHub API 或 AI 服务调用失败 |

前端展示时优先读取 `message` 字段，不直接展示原始异常信息。

## 3. 数据结构说明

### 3.1 ReviewAnalyzeRequest

PR 分析请求对象。

| 字段 | 类型 | 是否必填 | 示例 | 说明 |
| --- | --- | --- | --- | --- |
| prUrl | string | 是 | `https://github.com/owner/repo/pull/12` | GitHub Pull Request 链接 |

校验规则：

| 字段 | 规则 |
| --- | --- |
| prUrl | 不能为空 |
| prUrl | 必须符合 `https://github.com/{owner}/{repo}/pull/{pullNumber}` 格式 |
| pullNumber | 必须为正整数 |

示例：

```json
{
  "prUrl": "https://github.com/owner/repo/pull/12"
}
```

### 4.2 PR 分析接口

接口说明：

接收 GitHub Pull Request 链接，触发 PR 分析流程，并返回 AI Review 报告。

第一版 MVP 建议采用同步接口，便于前端联调和比赛演示。后续如果分析耗时较长，可以扩展为异步任务模式。

请求方式：

```http
POST /api/review-tasks
```

请求体：

| 字段 | 类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| prUrl | string | 是 | GitHub Pull Request 链接 |

请求示例：

```json
{
  "prUrl": "https://github.com/owner/repo/pull/12"
}
```

处理流程：

```text
1. 校验 prUrl 是否为空
2. 校验 prUrl 是否符合 GitHub PR 链接格式
3. 解析 owner、repo、pullNumber
4. 调用 GitHub API 获取 PR 基本信息
5. 调用 GitHub API 获取提交记录、变更文件和 diff
6. 对 diff 进行过滤、截断或摘要处理
7. 执行规则扫描
8. 调用大模型生成 Review 报告
9. 解析 AI 返回 JSON
10. 返回 ReviewReport
```

| taskId | number | 分析任务 ID |

## 5. 风险等级与风险类型说明

### 5.1 风险等级

| 风险等级 | 含义 | 展示建议 |
| --- | --- | --- |
| LOW | 低风险，通常是可维护性、测试补充或小范围优化建议 | 绿色 |
| MEDIUM | 中风险，建议开发者优先检查，可能影响异常流程或边界场景 | 橙色 |
| HIGH | 高风险，可能导致安全问题、线上故障或核心流程不可用 | 红色 |

风险评分建议：

| 分数范围 | 风险等级 |
| --- | --- |
| 0 - 39 | LOW |
| 40 - 69 | MEDIUM |
| 70 - 100 | HIGH |

### 5.2 风险类型

| 风险类型 | 含义 | 示例 |
| --- | --- | --- |
| BUG_RISK | 可能导致功能错误、空指针、异常流程或数据错误 | 变量未初始化、数组越界 |
| SECURITY_RISK | 安全相关风险，包括密钥、认证、权限、注入、敏感信息 | 硬编码密钥、SQL 注入、权限绕过 |
| PERFORMANCE_RISK | 性能风险，例如循环查询、无分页、大对象处理 | 循环内远程调用、重复查询 |
| MAINTAINABILITY | 可维护性风险，例如复杂逻辑、重复代码、边界不清晰 | 过长方法、重复代码 |
| STYLE | 代码风格、命名、格式等非阻塞问题 | 命名不规范、格式不统一 |
| TEST_RISK | 测试缺失、测试覆盖不足、关键场景未验证 | 核心逻辑缺少单元测试 |
| COMPATIBILITY | 兼容性风险，例如接口契约、依赖版本、配置变更影响 | API 契约变更未同步 |

说明：新增风险类型时，需要同步更新 Prompt、后端枚举、前端展示和本文档。

## 6. 常见错误说明

| 错误场景 | 建议 HTTP 状态码 | message 示例 | 前端处理建议 |
| --- | --- | --- | --- |
| PR 链接为空 | 400 | PR 链接不能为空 | 提示用户输入 PR 链接 |
| PR 链接格式错误 | 400 | PR 链接格式错误，请输入 GitHub Pull Request 地址 | 展示正确格式示例 |
| GitHub 仓库不存在 | 404 | GitHub 仓库不存在 | 提示检查 owner 和 repo |
| PR 不存在 | 404 | PR 不存在 | 提示检查 PR 编号 |
| GitHub API 限流 | 403 | GitHub API 限流，请稍后重试 | 提示稍后重试或检查 Token |
| 私有仓库无权限访问 | 403 | GitHub 仓库无权限访问，请检查 Token | 提示检查 GitHub Token 权限 |
| PR diff 为空 | 422 | PR diff 为空，暂无可分析内容 | 展示空状态 |
| PR diff 过大 | 200 / 422 | PR diff 过大，仅分析部分内容 | MVP 建议截断并在报告中提示 |
| AI 服务调用失败 | 502 | AI 服务调用失败，请稍后重试 | 提示稍后重试 |
| AI 返回格式解析失败 | 502 | AI 返回格式解析失败，请重新分析 | 提示重新分析 |
| 系统内部异常 | 500 | 系统内部异常，请稍后重试 | 展示通用错误提示 |

错误响应统一示例：

```json
{
  "code": 50000,
  "message": "AI 服务调用失败，请稍后重试",
  "data": null
}
```

## 7. 前后端联调说明

### 7.1 前端请求地址

前端统一请求相对路径：

```text
/api/review-tasks
```

不要在前端代码中写死后端完整地址。

### 7.2 Vite 代理配置

开发环境建议在 `frontend/vite.config.js` 中配置：

```js
server: {
  proxy: {
    '/api': {
      target: 'http://localhost:8080',
      changeOrigin: true
    }
  }
}
```

### 7.3 前端兼容策略

前端需要兼容以下情况：

1. 后端未启动：提示 `AI 分析失败，请稍后重试`。
2. `success=false`：展示后端返回的 `message`。
3. `data.prInfo` 缺失：展示默认占位，不让页面崩溃。
4. `riskItems` 为空：展示 `暂无风险建议，可能该 PR 风险较低`。
5. `testSuggestions` 为空：展示 `暂无测试建议。`。
6. 分析耗时较长：按钮展示 loading，避免重复提交。

### 7.4 推荐联调流程

```text
1. 启动 MySQL
2. 启动后端服务
3. 调用 GET /api/health 确认服务正常
4. 启动前端服务
5. 使用 Mock 数据确认页面展示正常
6. 关闭 Mock 开关，输入真实 GitHub PR 链接
7. 调用 POST /api/review-tasks
8. 检查 PR 基本信息、风险评分、风险列表和测试建议是否正常展示
9. 测试错误 PR 链接、无权限仓库、AI 服务异常等错误提示
```

### 7.5 PR 链接格式

当前仅支持 GitHub Pull Request 链接：

```text
https://github.com/{owner}/{repo}/pull/{pullNumber}
```

示例：

```text
https://github.com/owner/repo/pull/12
```

暂不支持 GitLab、Gitee、commit 链接、compare 链接和 issue 链接。

## 8. 后续扩展接口

以下接口不属于第一版 MVP 必做范围，可作为后续扩展方向：

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/reviews/{taskId}/rerun` | POST | 重新分析某次 PR |
| `/api/reviews/{taskId}/comments` | GET | 查询可复制 Review 评论列表 |
| `/api/reviews/{taskId}/files` | GET | 查询文件级分析结果 |
| `/api/github/preview` | POST | 仅预览 GitHub PR 基本信息，不触发 AI 分析 |
| `/api/model-configs` | GET / POST | 查询或保存模型配置 |
| `/api/model-configs/test` | POST | 测试模型连接 |
| `/api/prompts` | GET / PUT | 查询或更新 Prompt 模板 |

扩展原则：

1. 不影响 `/api/reviews/analyze` 的 MVP 主链路。
2. 不引入登录、权限、多租户等复杂能力。
3. 新增字段必须同步更新前端、后端 DTO 和本文档。
4. 涉及模型密钥、GitHub Token 的接口不得返回明文密钥。
