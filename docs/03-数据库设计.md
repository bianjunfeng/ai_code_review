# AI PR Review 助手数据库设计文档

## 1. 文档说明

本文档用于说明「AI PR Review 助手」的数据库设计方案，包括数据库选型、设计原则、核心表结构、索引设计、MySQL 建表 SQL、最小可用方案以及后续扩展方向。

本项目第一版定位为 3 天比赛 MVP，核心目标是跑通以下链路：

```text
输入 GitHub Pull Request 链接
→ 获取 PR 基本信息、变更文件和 diff
→ 执行规则扫描和 AI Review
→ 生成结构化 Review 报告
→ 前端展示 PR 总结、风险项、测试建议和最终结论
```

因此数据库设计优先保证简单、清晰、可落地，不追求复杂企业级建模。

## 2. 数据库选型

### 2.1 推荐选型

本项目第一版统一使用 MySQL 8.x 作为数据库。

| 数据库 | 使用场景 | 说明 |
| --- | --- | --- |
| MySQL 8.x | 本地开发、前后端联调、比赛演示、多人协作 | 稳定、常见、便于展示真实后端能力，适合保存 PR 分析历史和结构化 Review 结果 |

开发、联调和演示环境均建议保持 MySQL 版本一致，避免因为数据库方言差异导致 SQL、字段类型或时间字段行为不一致。

### 2.2 当前存储策略

当前采用「任务主表 + 明细表 + 完整 JSON 兜底」的轻量方案：

```text
review_task 保存任务状态、PR 基本信息、缓存字段、风险评分和报告摘要
review_file 保存 PR 变更文件、patch 摘要和文件级 AI 分析结果
review_comment 保存风险建议，支撑前端按风险等级和文件筛选
review_skill / review_skill_result 预留专项分析能力
review_task.result_json 保存完整 ReviewReport JSON，作为报告详情兜底数据
```

这样既能快速支持前端报告页展示，也能让任务中心、风险列表和缓存复用有稳定查询入口。

如果后续需要做风险统计、按文件筛选、按风险类型查询，可以逐步拆分：

```text
review_comment
review_file
review_skill_result
model_usage_log
```

### 2.3 当前不做复杂数据库设计的原因

本项目第一版暂不需要复杂数据库设计，原因如下：

1. 暂不做用户登录，不需要用户表和账号体系。
2. 暂不做多租户，不需要租户隔离字段。
3. 暂不做权限系统，不需要角色、权限、菜单等表。
4. 暂不做复杂任务队列，不需要单独的任务调度表。
5. 暂不保存完整源码内容，避免数据膨胀和隐私风险。
6. AI Review 报告可以通过 `LONGTEXT` 保存完整 JSON，降低实现复杂度。

## 3. 设计原则

数据库设计遵循以下原则：

| 原则 | 说明 |
| --- | --- |
| 简单优先 | 第一版优先保证核心功能可运行，不引入复杂模型 |
| 主表闭环 | `review_task` 可以单独保存一次完整分析结果 |
| 可扩展 | 风险项、文件变更、Skill 结果可作为扩展表拆分 |
| 字段清晰 | 表名和字段名使用小写下划线风格 |
| 逻辑外键 | 为了比赛开发效率，默认不强制使用数据库外键 |
| 隐私控制 | 不保存 GitHub Token、AI API Key 和完整源码 |
| 查询可用 | 为常见查询场景设计必要索引 |

通用字段规范：

| 规范项 | 要求 |
| --- | --- |
| 表名 | 小写下划线，例如 `review_task` |
| 字段名 | 小写下划线，例如 `created_at` |
| 主键 | `BIGINT AUTO_INCREMENT` |
| 时间字段 | `DATETIME` |
| 大文本字段 | `LONGTEXT` |
| 存储引擎 | `InnoDB` |
| 字符集 | `utf8mb4` |

## 5. 核心表设计

| repo_name | VARCHAR(150) | 否 | NULL | GitHub 仓库名称 |
| pr_number | INT | 否 | NULL | Pull Request 编号 |

| pr_author | VARCHAR(100) | 否 | NULL | PR 作者 |
| source_branch | VARCHAR(200) | 否 | NULL | 源分支 |
| target_branch | VARCHAR(200) | 否 | NULL | 目标分支 |
| status | VARCHAR(30) | 是 | PENDING | 任务状态 |
| risk_score | INT | 否 | NULL | 风险评分，范围 0 到 100 |
| risk_level | VARCHAR(20) | 否 | NULL | 风险等级：LOW / MEDIUM / HIGH / CRITICAL |
| summary | TEXT | 否 | NULL | PR 总结 |
| final_review | TEXT | 否 | NULL | 最终 Review 结论 |

## 6. 状态与枚举说明

### 6.1 任务状态

| 状态 | 含义 | 使用说明 |
| --- | --- | --- |
| PENDING | 任务已创建，等待执行 | 异步任务创建后使用 |
| FETCHING_PR | 正在获取 GitHub PR 信息 | 正在调用 GitHub API 获取 PR 基本信息 |
| PARSING_DIFF | 正在解析 diff | 正在获取 changed files 和 diff patch |
| REVIEWING | 正在进行 AI Review | 正在调用大模型进行代码评审 |
| SUMMARIZING | 正在生成总结 | 正在汇总 Review 结果 |
| SUCCESS | 任务执行成功 | 已生成 Review 报告 |
| FAILED | 任务执行失败 | GitHub API、AI 调用或解析异常 |
| CANCELLED | 任务已取消 | 任务被手动取消 |

状态流转：

```text
PENDING → FETCHING_PR → PARSING_DIFF → REVIEWING → SUMMARIZING → SUCCESS
```

失败时：

```text
任意未完成状态 → FAILED
```

取消时：

```text
任意未完成状态 → CANCELLED
```

### 6.2 风险等级

| 风险等级 | 含义 | 展示建议 |
| --- | --- | --- |
| LOW | 低风险，通常是可维护性或测试补充建议 | 绿色 |
| MEDIUM | 中风险，建议优先检查，可能影响边界场景 | 橙色 |
| HIGH | 高风险，可能导致安全问题、线上故障或核心流程不可用 | 红色 |
| CRITICAL | 严重风险，可能导致严重安全问题、数据破坏或核心链路不可用 | 深红色 |

最终 `risk_score` 和 `risk_level` 由后端 `RiskScoreCalculator` 基于已保存的 Review Comment 固定规则计算，不直接采用 AI 输出的总评分。

| 分数范围 | 风险等级 |
| --- | --- |
| 0 - 30 | LOW |
| 31 - 60 | MEDIUM |
| 61 - 85 | HIGH |
| 86 - 100 | CRITICAL |

### 6.3 风险类型

| 风险类型 | 含义 | 示例 |
| --- | --- | --- |
| BUG_RISK | 可能导致功能错误、空指针、异常流程或数据错误 | 变量未初始化、数组越界 |
| SECURITY_RISK | 安全相关风险，包括密钥、认证、权限、注入、敏感信息 | 硬编码密钥、SQL 注入、权限绕过 |
| PERFORMANCE_RISK | 性能风险，例如循环查询、无分页、大对象处理 | 循环内远程调用、重复查询 |
| MAINTAINABILITY | 可维护性风险，例如复杂逻辑、重复代码、边界不清晰 | 过长方法、重复代码 |
| STYLE | 代码风格、命名、格式等非阻塞问题 | 命名不规范、格式不统一 |
| TEST_RISK | 测试缺失、测试覆盖不足、关键场景未验证 | 核心逻辑缺少单元测试 |
| COMPATIBILITY | 兼容性风险，例如接口契约、依赖版本、配置变更影响 | API 契约变更未同步 |

说明：如果后端实现阶段采用更少的风险枚举，需要在接口文档、Prompt 文档、前端展示和数据库文档中保持一致。

## 8. MySQL 建表 SQL

说明：

1. 使用 `InnoDB` 存储引擎。
2. 使用 `utf8mb4` 字符集。
3. 为了比赛开发效率，默认不使用数据库外键约束，使用 `task_id` 作为逻辑外键。
4. `result_json`、`raw_output` 使用 `LONGTEXT` 保存大文本。
5. 时间字段统一使用 `DATETIME`。

```sql
CREATE TABLE IF NOT EXISTS review_task (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    pr_url VARCHAR(500) NOT NULL COMMENT 'GitHub Pull Request链接',
    owner_name VARCHAR(100) DEFAULT NULL COMMENT 'GitHub仓库owner',
    repo_name VARCHAR(150) DEFAULT NULL COMMENT 'GitHub仓库名称',
    pr_number INT DEFAULT NULL COMMENT 'Pull Request编号',
    pr_title VARCHAR(500) DEFAULT NULL COMMENT 'PR标题',
    pr_author VARCHAR(100) DEFAULT NULL COMMENT 'PR作者',
    source_branch VARCHAR(200) DEFAULT NULL COMMENT '源分支',
    target_branch VARCHAR(200) DEFAULT NULL COMMENT '目标分支',
    status VARCHAR(30) NOT NULL DEFAULT 'PENDING' COMMENT '任务状态：PENDING/FETCHING_PR/PARSING_DIFF/REVIEWING/SUMMARIZING/SUCCESS/FAILED/CANCELLED',
    risk_score INT DEFAULT NULL COMMENT '风险评分，范围0到100',
    risk_level VARCHAR(20) DEFAULT NULL COMMENT '风险等级：LOW/MEDIUM/HIGH/CRITICAL',
    summary TEXT DEFAULT NULL COMMENT 'PR总结',
    final_review TEXT DEFAULT NULL COMMENT '最终Review结论',
    result_json LONGTEXT DEFAULT NULL COMMENT '完整AI Review结果JSON',
    error_message TEXT DEFAULT NULL COMMENT '任务失败原因',
    head_sha VARCHAR(64) DEFAULT NULL COMMENT 'PR head commit sha，用于缓存命中判断',
    base_sha VARCHAR(64) DEFAULT NULL COMMENT 'PR base commit sha',
    model_name VARCHAR(100) DEFAULT NULL COMMENT '执行评审使用的模型名称',
    prompt_version VARCHAR(50) DEFAULT 'v1' COMMENT 'Prompt版本',
    cached_from_task_id BIGINT DEFAULT NULL COMMENT '命中缓存时关联的历史任务ID',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    INDEX idx_pr_url (pr_url),
    INDEX idx_repo_pr (owner_name, repo_name, pr_number),
    INDEX idx_created_at (created_at),
    INDEX idx_risk_level (risk_level),
    INDEX idx_status (status),
    INDEX idx_review_cache (owner_name, repo_name, pr_number, head_sha, model_name, prompt_version, status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='PR分析任务表';

CREATE TABLE IF NOT EXISTS review_file (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    task_id BIGINT NOT NULL COMMENT '关联review_task.id',
    file_path VARCHAR(600) DEFAULT NULL COMMENT '文件路径',
    file_status VARCHAR(30) DEFAULT NULL COMMENT '文件状态：added/modified/removed/renamed',
    language VARCHAR(50) DEFAULT NULL COMMENT '语言类型',
    additions INT NOT NULL DEFAULT 0 COMMENT '新增行数',
    deletions INT NOT NULL DEFAULT 0 COMMENT '删除行数',
    changes INT NOT NULL DEFAULT 0 COMMENT '总变更行数',
    patch LONGTEXT DEFAULT NULL COMMENT 'Diff patch内容',
    ai_summary TEXT DEFAULT NULL COMMENT 'AI文件级总结',
    skipped TINYINT NOT NULL DEFAULT 0 COMMENT '是否跳过AI分析：0否，1是',
    skip_reason VARCHAR(500) DEFAULT NULL COMMENT '跳过原因',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    INDEX idx_task_id (task_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='PR变更文件表';

CREATE TABLE IF NOT EXISTS review_comment (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    task_id BIGINT NOT NULL COMMENT '关联review_task.id',
    file_path VARCHAR(600) DEFAULT NULL COMMENT '风险所在文件路径',
    line_number INT DEFAULT NULL COMMENT '代码行号',
    risk_type VARCHAR(50) DEFAULT NULL COMMENT '风险类型',
    risk_level VARCHAR(20) DEFAULT NULL COMMENT '风险等级：LOW/MEDIUM/HIGH/CRITICAL/INFO',
    title VARCHAR(300) DEFAULT NULL COMMENT '问题标题',
    description TEXT DEFAULT NULL COMMENT '问题描述',
    reason TEXT DEFAULT NULL COMMENT '风险原因说明',
    suggestion TEXT DEFAULT NULL COMMENT '修改建议',
    confidence DECIMAL(4,2) DEFAULT NULL COMMENT '置信度：0到1之间的小数',
    need_human_check TINYINT NOT NULL DEFAULT 0 COMMENT '是否需要人工确认：0否，1是',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    INDEX idx_task_id (task_id),
    INDEX idx_risk_level (risk_level),
    INDEX idx_risk_type (risk_type),
    INDEX idx_task_level (task_id, risk_level)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='AI Review建议表';

CREATE TABLE IF NOT EXISTS review_skill (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    skill_code VARCHAR(100) NOT NULL COMMENT 'Skill编码',
    skill_name VARCHAR(100) NOT NULL COMMENT 'Skill名称',
    skill_type VARCHAR(50) NOT NULL COMMENT 'Skill类型',
    description VARCHAR(500) DEFAULT NULL COMMENT 'Skill描述',
    supported_languages VARCHAR(200) DEFAULT NULL COMMENT '支持的语言列表',
    enabled TINYINT NOT NULL DEFAULT 1 COMMENT '是否启用：0否，1是',
    priority INT NOT NULL DEFAULT 100 COMMENT '执行优先级，数值越小优先级越高',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    UNIQUE KEY uk_review_skill_code (skill_code),
    INDEX idx_review_skill_enabled (enabled),
    INDEX idx_review_skill_priority (priority)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='Review Skill配置表';

CREATE TABLE IF NOT EXISTS review_skill_result (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    task_id BIGINT NOT NULL COMMENT '关联review_task.id',
    skill_name VARCHAR(100) NOT NULL COMMENT 'Skill名称，例如PRSummarySkill',
    success TINYINT NOT NULL DEFAULT 1 COMMENT '是否执行成功：0否，1是',
    summary TEXT DEFAULT NULL COMMENT 'Skill输出摘要',
    raw_output LONGTEXT DEFAULT NULL COMMENT '模型或规则扫描原始输出',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    INDEX idx_review_skill_result_task_id (task_id),
    INDEX idx_review_skill_result_skill_name (skill_name)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='Skill执行结果表';
```

## 9. 第一版最小可用数据库方案

本节是早期 MVP 备选方案。当前 `dev` 已经实现 `review_task`、`review_file`、`review_comment`，并预留了 `review_skill`、`review_skill_result`，因此后续不再建议退回单表方案。

如果时间非常紧，早期第一版可以只实现一张表：

```text
review_task
```

通过 `result_json` 保存完整 Review 报告，前端详情页可以直接读取并展示完整 JSON。

### 9.1 最小字段建议

最小可用字段：

| 字段名 | 说明 |
| --- | --- |
| id | 主键 |
| pr_url | PR 链接 |
| status | 分析状态 |
| risk_score | 风险评分 |
| risk_level | 风险等级 |
| summary | PR 总结 |
| final_review | 最终 Review 结论 |
| result_json | 完整 ReviewReport JSON |
| error_message | 失败原因 |
| created_at | 创建时间 |
| updated_at | 更新时间 |

### 9.2 优点

1. 实现简单。
2. 适合 3 天比赛。
3. 前端可以直接读取完整 JSON。
4. 不需要处理复杂表关联。
5. 后续可以逐步拆分风险项表、文件变更表和 Skill 执行结果表。

### 9.3 缺点

1. 不方便按风险项统计。
2. 不方便按风险类型做筛选。
3. 不方便做复杂查询。
4. 不利于后续数据分析。
5. 如果 `result_json` 长期保存过多内容，可能导致表体积增长较快。

### 9.4 推荐落地方式

第一版开发顺序建议：

```text
1. 先实现 review_task
2. result_json 保存完整报告
3. 前端直接展示 result_json 中的数据
4. 如果时间允许，再补 review_comment
5. 后续再补 review_file 和 review_skill_result
```

## 10. 数据安全与隐私说明

本项目会处理 GitHub PR diff 和 AI 分析结果，需要注意数据安全和隐私。

安全要求：

1. 不保存 GitHub Token。
2. 不保存 AI API Key。
3. 不建议长期保存完整源码内容。
4. diff 内容如果需要保存，应优先保存摘要。
5. 本地配置文件不得提交到 Git。
6. 敏感字段如 token、secret、password 不应明文入库。
7. 生产环境应使用环境变量或配置中心管理密钥。
8. 日志中不得打印完整 Token、API Key、数据库密码。
9. 如果需要展示密钥信息，必须脱敏，例如 `sk-****abcd`。

不建议入库的内容：

| 内容 | 原因 |
| --- | --- |
| GitHub Token | 属于访问凭证，泄露后可能访问私有仓库 |
| AI API Key | 属于模型服务凭证，泄露后可能产生费用风险 |
| 数据库密码 | 属于基础设施凭证 |
| 完整源码快照 | 数据量大，并且可能包含业务隐私 |
| 未脱敏日志 | 可能包含请求头、Token 或模型返回敏感内容 |

建议保存的内容：

| 内容 | 说明 |
| --- | --- |
| PR 链接 | 便于追踪分析来源 |
| PR 标题和作者 | 便于历史记录展示 |
| 风险评分和风险等级 | 便于快速筛选 |
| AI 总结和最终结论 | 便于报告展示 |
| 风险项描述和建议 | 便于前端展示和复制 Review 评论 |
| diff 摘要 | 便于回看分析依据，避免保存完整代码 |

## 12. 升级方案数据库设计

本节对应 `docs/04-接口设计.md` 中的升级接口，用于支撑 PR 工作台、任务中心、缓存复用、模型用量监控、Skill 中心和执行轨迹。

### 12.1 当前已落地的升级字段

`review_task` 已经承担任务中心和缓存复用的核心查询，因此需要保留以下字段：

| 字段 | 作用 | 使用场景 |
| --- | --- | --- |
| owner_name | 仓库 owner | PR 工作台、任务中心筛选 |
| repo_name | 仓库名 | PR 工作台、任务中心筛选 |
| pr_number | PR 编号 | 定位同一个 PR |
| head_sha | PR head commit sha | 判断同一个 PR 当前版本是否已有成功报告 |
| base_sha | PR base commit sha | 记录 PR 对比基线 |
| model_name | 模型名称 | 缓存 key，避免不同模型结果混用 |
| prompt_version | Prompt 版本 | 缓存 key，避免 Prompt 升级后复用旧报告 |
| cached_from_task_id | 缓存来源任务 ID | 前端展示缓存命中来源 |

缓存命中推荐条件：

```text
owner_name
repo_name
pr_number
head_sha
model_name
prompt_version
status = SUCCESS
```

推荐索引：

```sql
CREATE INDEX idx_review_cache
ON review_task(owner_name, repo_name, pr_number, head_sha, model_name, prompt_version, status);
```

### 12.2 任务中心查询设计

任务中心接口 `GET /api/review-tasks` 主要依赖 `review_task`。

常见筛选条件：

```text
status
risk_level
owner_name
repo_name
pr_title / pr_author / repo_name 模糊搜索
created_at 时间范围
```

推荐索引：

```sql
CREATE INDEX idx_status ON review_task(status);
CREATE INDEX idx_risk_level ON review_task(risk_level);
CREATE INDEX idx_created_at ON review_task(created_at);
CREATE INDEX idx_repo_pr ON review_task(owner_name, repo_name, pr_number);
```

说明：

```text
1. keyword 模糊搜索第一版可以直接 LIKE。
2. 数据量增长后再考虑全文索引或专门搜索服务。
3. task 列表不返回 patch、raw_output 等大字段。
```

### 12.3 PR 工作台本地状态设计

PR 工作台接口 `GET /api/github/pulls` 的 GitHub PR 列表来自 GitHub API，本地只补充历史评审状态。

本地状态查询可以基于：

```sql
SELECT *
FROM review_task
WHERE owner_name = ?
  AND repo_name = ?
  AND pr_number IN (...)
ORDER BY created_at DESC;
```

前端需要的字段：

```text
reviewed
latest_task_id
latest_task_status
latest_risk_level
latest_risk_score
cached_available
```

这些字段不需要单独建表，第一版可由 `review_task` 聚合得到。

### 12.4 模型用量监控表

模型用量监控用于展示调用次数、Token 消耗、耗时、成功率和失败明细。该表属于 P1/P2 扩展，当前可先设计，后续在 AI Client 层统一写入。

建议新增表：

```sql
CREATE TABLE IF NOT EXISTS model_usage_log (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    task_id BIGINT DEFAULT NULL COMMENT '关联review_task.id',
    file_id BIGINT DEFAULT NULL COMMENT '关联review_file.id',
    provider VARCHAR(100) DEFAULT NULL COMMENT '模型供应商或协议类型',
    model_name VARCHAR(100) DEFAULT NULL COMMENT '模型名称',
    call_type VARCHAR(50) DEFAULT NULL COMMENT '调用类型：FILE_REVIEW/PR_SUMMARY/TEST_SUGGESTION等',
    prompt_tokens INT DEFAULT 0 COMMENT 'Prompt token数量',
    completion_tokens INT DEFAULT 0 COMMENT 'Completion token数量',
    total_tokens INT DEFAULT 0 COMMENT '总token数量',
    latency_ms INT DEFAULT NULL COMMENT '调用耗时，单位毫秒',
    success TINYINT NOT NULL DEFAULT 1 COMMENT '是否成功：0否，1是',
    error_message TEXT DEFAULT NULL COMMENT '失败原因摘要',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    INDEX idx_model_usage_task_id (task_id),
    INDEX idx_model_usage_model_name (model_name),
    INDEX idx_model_usage_created_at (created_at),
    INDEX idx_model_usage_success (success)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='模型调用用量日志表';
```

安全要求：

```text
1. 不保存完整 Prompt。
2. 不保存完整 AI 原始响应。
3. 不保存 API Key。
4. error_message 只保存摘要，避免包含敏感代码。
```

### 12.5 Skill 表升级方向

当前已预留：

```text
review_skill
review_skill_result
```

后续如果做 Skill Pipeline，建议增强 `review_skill_result`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| file_id | BIGINT | 对应文件 ID，PR 级 Skill 可为空 |
| file_path | VARCHAR(600) | 文件路径，方便前端展示 |
| skill_code | VARCHAR(100) | Skill 编码 |
| phase | VARCHAR(50) | FILE_REVIEW / PR_SUMMARY / FINAL_REVIEW |
| error_message | TEXT | 单个 Skill 失败原因 |

增强后的建议 SQL：

```sql
ALTER TABLE review_skill_result
ADD COLUMN file_id BIGINT DEFAULT NULL COMMENT '关联review_file.id',
ADD COLUMN file_path VARCHAR(600) DEFAULT NULL COMMENT '文件路径',
ADD COLUMN skill_code VARCHAR(100) DEFAULT NULL COMMENT 'Skill编码',
ADD COLUMN phase VARCHAR(50) DEFAULT 'FILE_REVIEW' COMMENT '执行阶段',

CREATE INDEX idx_review_skill_result_file_id ON review_skill_result(file_id);
CREATE INDEX idx_review_skill_result_skill_code ON review_skill_result(skill_code);
```

### 12.6 执行轨迹设计
