## P0 已实现功能

1. **创建任务立即返回** — POST /api/review-tasks 不等待 AI 完成，毫秒级响应
2. **报告页轮询** — ReviewReportView 每 2s 拉取进度，SUCCESS 后自动加载
3. **数据库缓存复用** — 同 PR 同 commit 同模型同 Prompt 版本命中后创建新 SUCCESS 任务，并复制历史任务的文件和评论数据
4. **Diff 预处理** — DiffPreprocessor 在保存文件前过滤 lock 文件/二进制/空 patch，并按优先级应用大 PR 限制
5. **Patch 截断** — 单文件超过 `review.diff.max-file-patch-chars` 时截断保存并标记 `truncated=true`
6. **进度追踪** — ReviewTaskDetailVO 返回 progressPercent/currentStep/文件计数
7. **SCORING 状态** — 风险评分阶段独立展示

## 阶段 3：大 PR 限制和缓存命中完整复制

状态：✅ 已完成

1. `review.diff.max-files` 控制单个 PR 最多进入 AI 分析的文件数，默认 30。
2. `review.diff.max-file-patch-chars` 控制单文件 patch 最大分析字符数，默认 12000。
3. `review.diff.max-total-patch-chars` 控制单个 PR 累计 patch 最大分析字符数，默认 100000。
4. `review_file` 记录 `original_patch_length`、`analyzed_patch_length`、`truncated`，前端可展示截断提示。
5. 超过文件数或总 patch 预算的文件会保留文件记录，并以 `FILE_COUNT_LIMIT` 或 `TOTAL_PATCH_LIMIT` 标记为跳过。
6. 缓存命中时不再只复制任务摘要，会把原任务的 `review_file` 和 `review_comment` 复制到新 `taskId`，保证报告、文件视图、评论视图完整。

## P1 已实现功能

1. **文件级并发评审** — CompletableFuture + fileReviewExecutor，默认 3 并发
2. **单文件超时控制** — 每个文件 60s 硬超时，超时标记失败不中断任务
3. **智能重试** — 仅对 5xx/IOException 重试 1 次，4xx 不重试避免浪费 Token
