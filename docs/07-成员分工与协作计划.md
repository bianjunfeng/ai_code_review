# AI PR Review 助手成员分工与协作计划

## 1. 文档说明

本文档用于说明 AI PR Review 助手项目在两人协作、两天开发周期内的成员分工方式、任务边界、协作流程、交付内容和验收标准。

本项目采用 AI 工具辅助软件设计与开发。由于开发周期较短，团队不采用传统“前端 / 后端”单一分工方式，而采用 **全阶段双闭环分工模式**。两名成员均参与需求分析、技术设计、功能开发、联调测试、文档整理和最终展示，只是在业务闭环上各自承担不同主责。

------

## 2. 项目开发目标

本项目目标是在两天内完成 AI PR Review 助手的 MVP 版本，实现以下核心流程：

```text
用户输入 GitHub Pull Request 链接
→ 系统解析 PR 地址
→ 系统获取 PR 基本信息和代码 Diff
→ 系统调用大模型进行代码评审
→ 系统生成 PR 总结、风险识别和 Review 建议
→ 前端页面展示结构化 Review 报告
```

MVP 阶段重点保证核心链路可运行、可展示、可说明，不追求完整企业级功能。

------

## 3. 分工原则

本项目采用 **全阶段双闭环分工**。

所谓全阶段，是指两名成员都参与：

```text
需求分析
技术设计
功能开发
接口联调
系统测试
文档整理
最终展示
```

所谓双闭环，是指两名成员分别负责一个完整业务链路，而不是简单拆成前端和后端。

具体分为：

```text
成员 A：PR 获取与任务闭环负责人
成员 B：AI Review 与报告闭环负责人
```

这种分工方式的优势：

1. 避免传统前后端分工导致的等待和阻塞。
2. 每名成员都能参与完整软件开发流程。
3. 每名成员都能讲清楚自己负责的业务闭环。
4. 适合使用 AI 编程工具快速生成、修改和联调代码。
5. 更符合短周期项目的交付要求。

## 18. 分工总结

本项目不采用单纯的前后端分工，也不采用“一个人开发、一个人展示”的分工方式，而采用全阶段双闭环分工。

成员 A 负责 **PR 获取与任务闭环**，覆盖 PR 链接解析、GitHub API 对接、Diff 获取、任务创建、任务状态流转、数据存储、报告接口、异常处理、相关文档和最终联调。

成员 B 负责 **AI Review 与报告闭环**，覆盖 Prompt 设计、大模型调用协作、AI 输出解析、风险类型设计、Review 建议生成、报告展示、误报漏报控制说明、相关文档和最终联调。

两名成员均参与需求、设计、开发、测试、文档和最终展示，保证项目在两天内完成核心 MVP，并能够清晰说明系统的设计思路、实现过程和未来扩展方向。
