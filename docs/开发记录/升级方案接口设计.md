# AI PR Review 升级方案接口设计

## 1. 文档目的

本文档承接 `docs/开发记录/升级方案.md` 和 `docs/开发记录/前端升级.md`，把后续升级方向收敛成可实现的 REST API 契约。

当前项目已经具备基础链路：

```text
输入 PR 链接
→ 创建 Review 任务
→ GitHub API 获取 PR 信息和 Diff
→ AI Review
→ 任务状态轮询
→ 展示 Review 报告
```

升级目标是把系统从“单页输入 PR 链接工具”升级为：

```text
AI PR Review 工作台
→ PR 列表
→ 评审任务中心
→ 报告详情
→ 文件维度建议
→ 缓存复用
→ 模型用量监控
→ Skill / Agent 扩展入口
```

---

## 2. 接口通用约定

### 2.1 基础路径

```text
http://localhost:8080/api
```

### 2.2 统一响应结构

所有接口统一返回 `Result<T>`：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

失败响应：

```json
{
  "code": 40001,
  "message": "PR 链接格式错误，请输入 GitHub Pull Request 地址",
  "data": null
}
```

### 2.3 分页响应结构

新增列表类接口统一使用 `PageVO<T>`：

```json
{
  "records": [],
  "page": 1,
  "pageSize": 10,
  "total": 42,
  "pages": 5
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| records | array | 当前页数据 |
| page | number | 当前页，从 1 开始 |
| pageSize | number | 每页条数 |
| total | number | 总记录数 |
| pages | number | 总页数 |

### 2.4 默认分页参数

```text
page=1
pageSize=10
```

约束：

```text
page >= 1
1 <= pageSize <= 50
```

## 4. P0 接口：GitHub PR 列表工作台

### 4.1 查询仓库 PR 列表

用于把首页从“手动粘贴 PR 链接”升级为“选择仓库 PR 后开始评审”。

```http
GET /api/github/pulls
```

当前状态：后端已实现。该接口只获取 GitHub PR 列表和本地评审状态，不拉取 changed files 和 diff，避免列表页过慢。

Query 参数：

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| owner | string | 是 | 无 | 仓库 owner，例如 `crash73` |
| repo | string | 是 | 无 | 仓库名，例如 `test-for-PRreview` |
| state | string | 否 | `open` | `open`、`closed`、`all` |
| page | number | 否 | `1` | 当前页 |
| pageSize | number | 否 | `10` | 每页数量，最大 50 |

示例：

```http
GET /api/github/pulls?owner=crash73&repo=test-for-PRreview&state=open&page=1&pageSize=10
```

后端调用 GitHub API：

```http
GET /repos/{owner}/{repo}/pulls?state=open&per_page=10&page=1
```

响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "records": [
      {
        "owner": "crash73",
        "repo": "test-for-PRreview",
        "pullNumber": 1,
        "title": "feat: 添加认证服务演示变更",
        "author": "crash73",
        "state": "OPEN",
        "sourceBranch": "feature/review-demo",
        "targetBranch": "main",
        "htmlUrl": "https://github.com/crash73/test-for-PRreview/pull/1",
        "createdAt": "2026-05-30 19:30:00",
        "updatedAt": "2026-05-30 19:35:00",
        "draft": false,
        "reviewed": true,
        "latestTaskId": 12,
        "latestTaskStatus": "SUCCESS",
        "latestRiskLevel": "HIGH",
        "latestRiskScore": 78,
        "cachedAvailable": true
      }
    ],
    "page": 1,
    "pageSize": 10,
    "total": null,
    "pages": null
  }
}
```

说明：

```text
1. GitHub PR 列表接口本身不返回 total，第一版允许 total/pages 为 null。
2. reviewed/latestTaskId/latestRiskLevel/cachedAvailable 由本地 review_task 表补充。
3. 第一版不强制返回 additions/deletions/changedFiles，避免列表页对每个 PR 额外请求详情。
4. 点击“开始评审”时再复用 POST /api/review-tasks。
```

### 5.2 创建 Review 任务

当前已实现，升级后继续作为 PR 工作台的核心动作。

```http
POST /api/review-tasks
```

请求：

```json
{
  "prUrl": "https://github.com/crash73/test-for-PRreview/pull/1",
  "forceRefresh": false
}
```

响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "taskId": 12,
    "status": "SUCCESS",
    "cached": true,
    "cachedFromTaskId": 12
  }
}
```

说明：

```text
1. forceRefresh=false 时，后端优先查缓存。
2. 命中缓存时直接返回历史成功任务 taskId，前端不需要长时间轮询。
3. forceRefresh=true 时，忽略缓存并创建新任务。
4. 前端重新分析按钮必须传 forceRefresh=true。
```
