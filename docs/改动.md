## 本次架构调整

本次从文档反推后端主线，将后端从“GitHub 预览 + mock 报告”调整为“Review 任务闭环”：

```text
ReviewTaskController
→ ReviewTaskService
→ GitHubPullRequestService
→ GitHubClient
→ ReviewTaskStore
→ ReviewReportService
→ VO
```

核心逻辑：

1. `GitHubController` 继续保留 `/api/github/preview`，用于 PR 预览。
2. `ReviewTaskController` 成为主入口，支持创建任务、查询详情、查询文件、查询评论、查询报告。
3. `GitHubPullRequestService` 不再只面向 `GitHubPrPreviewVO`，新增内部快照模型 `GitHubPullRequest` / `GitHubChangedFile`。
4. `ReviewTaskService` 负责创建任务、状态流转、保存 PR 信息和 changed files。
5. `ReviewReportService` 不再返回硬编码 mock，而是从任务、文件、评论聚合报告。
6. 当前 MVP 使用 `InMemoryReviewTaskStore`，后续接 MySQL 时替换为 Mapper 实现。

## 当前任务状态逻辑

```text
PENDING
→ FETCHING_PR
→ PARSING_DIFF
→ REVIEWING
```

说明：

```text
当前创建任务时同步完成 GitHub PR 获取和文件保存，因此成功创建后状态为 REVIEWING，表示等待 AI Review 接入。
如果 GitHub 获取失败，任务会标记 FAILED，并通过统一异常返回友好错误。
```
